FFmpeg Video Pipeline Architecture

The 3 Core Moving Parts of Native QuickTime & Multi-Player Chapter Processing

Part 1

Sidecar Asset Creation

Before video encoding starts, the setup phase reads chapter definitions and generates two synchronized text sidecar files in the per-clip log directory (02_clips/Raisanen-1987a-log/):

  • meta_01.txt (FFmpeg Metadata): Standard ;FFMETADATA1 structure. FFmpeg uses this to write ISO global container chapters (chpl atom) for VLC, IINA, and ffprobe.
  • meta_01.vtt (WebVTT Format): Standard timed text syntax (00:00:00.000 --> 00:00:10.000). FFmpeg encodes this stream directly as 3GPP MOV text (-c:s mov_text) so macOS QuickLook and QuickTime Player construct native track reference bindings (tref).
Part 2

Stage 1: Pre-trim & Intermediate MKV

Decodes raw analog transfers, applies precise frame seeking (-ss / -to), and runs required audio/video filtering chains (e.g., yadif deinterlacing or crop adjustments).

  • Lossless Intermediate: Encodes output to /tmp/stage1_<clip_id>.mkv using -c:v utvideo -c:a pcm_s16le.
  • Architectural Purpose: Isolates heavy filtering/seeking from compressed delivery encoding. Prevents pipeline stalls, timestamp drift, and memory pipe crashes during downstream MP4 muxing.
Part 3

Stage 2: Final Encode & Dual Chapter Muxing

Reads the intermediate file (/tmp/stage1_<clip_id>.mkv) along with both pre-generated sidecar files to produce the delivery MP4.

  • Audio Handling: Passes -channel_layout stereo explicitly to suppress automatic layout guessing warnings on raw PCM inputs.
  • Encoding: Generates distribution-grade H.264 video (-c:v libx264 -crf 22) and AAC audio (-c:a aac -b:a 192k).
  • Dual Muxing: Muxes global ISO container metadata via -map_chapters 1 while simultaneously encoding stream 2:s:0 as -c:s mov_text, creating universal native chapter playback across macOS QuickTime, Finder QuickLook, VLC, and IINA.
